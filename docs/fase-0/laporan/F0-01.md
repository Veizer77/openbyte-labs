## Ringkasan

Versi dependency langsung dikunci persis. Runtime lokal yang terlihat adalah Node `26.8.2` dan pnpm `12.3.4`. `package.json` mengizinkan Node `^22.23.4 || ^24.22.1 || >=26.0.0`, sedangkan CI menargetkan Node `22.23.4`. Kompatibilitas lokal Node 26 tidak membuktikan target Node 22.

Audit moderate yang tercatat pada verifikasi reset keluar dengan exit code 1: `esbuild@0.18.20`, GHSA-67mh-4wv8-2f99, melalui `@esbuild-kit/core-utils` dan `@esbuild-kit/esm-loader` bersama `drizzle-kit`. Audit pada ambang high keluar 0, tetapi dependency tidak bersih pada ambang moderate. Metadata Better Auth 1.7.14 menandai peer `drizzle-kit` sebagai optional; `drizzle-kit` juga dependency dev langsung. Graph pnpm menunjukkan jalur peer tersebut, jadi keberadaan paket dalam artefak production belum dibuktikan atau disangkal oleh audit ini. Jangan menyebut temuan sudah tidak terekspos sebelum menguji clean production install.

## Advisory dan rekomendasi

1. Pertahankan temuan `esbuild@0.18.20` sebagai risiko terbuka sampai clean install/audit di lingkungan terisolasi. `pnpm why esbuild` saat ini menunjukkan versi `0.18.20`, `0.25.12`, dan `0.28.2`; loader `@esbuild-kit/*` juga muncul di rantai `drizzle-kit` dan berstatus deprecated menurut catatan instalasi/audit yang tersedia.
2. Evaluasi upgrade exact-pinned `drizzle-kit` yang kompatibel dengan Better Auth/Drizzle dan membuang loader rentan. Baca changelog/API versi yang dipilih dan uji `generate`, migrator, build, typecheck, serta clean install sebelum integrasi.
3. Jangan menambahkan override `esbuild` secara membabi-buta. Override hanya boleh diusulkan dengan bukti rentang peer, resolusi transitive, uji migrasi/build dan persetujuan pemilik.
4. Jalankan ulang audit full dan production pada lockfile hasil perubahan. Karena peer optional dapat membuat graph audit tampak berbeda dari artefak deploy, verifikasi isi clean production install secara eksplisit.
