## Protokol integrasi setelah checkpoint disetujui

1. Koordinator cocokkan `git status`, daftar path stage eksplisit, dan diff/berkas baru terhadap daftar yang disetujui; pisahkan perubahan pribadi/tool dan catat SHA checkpoint baru. Minta otorisasi commit itu sendiri, jangan menganggap permintaan ini izin push. Kirim SHA, branch asal dan batas wilayah tulis ke masing-masing agent; tolak branch dari HEAD lama.
2. Bekukan F0-06 dan prasyarat F0-07 sebelum membuka penulisan konsumen. Tiap penyerahan memuat diff, laporan, tes sebenarnya, dan daftar file di luar wilayah (harus disetujui lebih dahulu). Review perubahan keamanan, scope, dan secret sebelum integrasi; jangan merge otomatis hanya karena tes branch lulus.
3. Integrasikan patch dependency/config lewat koordinator **sekali** dan audit ulang lockfile/target runtime. Integrasikan schema/migrasi dari DB tunggal setelah review SQL dan hanya pada target tes yang diizinkan. Setelah keduanya stabil, baru integrasikan policy, auth, media, route dan konsumen menurut dependensi; konflik ditangani bersama pemilik file, bukan overwrite.
4. Pada hasil gabungan ulangi lint, typecheck, unit/integrasi terkait, `check:portability`, `check:access` sesuai cakupan nyata, audit dependency, build dan E2E untuk route/runtime; DB/Neon/R2/Docker/restore hanya dengan target tes dan izin khusus. Catat SHA hasil gabungan serta run/skip/gagal tanpa menyamakan tes lokal dengan bukti cloud. Perubahan schema/dependency/konsumen setelah run mengharuskan tes terdampak diulang.
