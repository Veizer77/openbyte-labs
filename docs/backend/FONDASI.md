# Status backend dan integrasi Rilis 1

**Pembaruan terakhir: 31 Oktober 2026.** Dokumen ini merangkum backend, data dev, dan integrasi UI terpilih; bukan pernyataan bahwa Rilis 1 atau produksi sudah selesai.

Database Neon dev telah dimigrasi dan di-seed. Identitas target operasional tidak dicatat dalam dokumentasi repo. Katalog publik memakai data database pada beranda (Settings serta section layanan/proyek/FAQ), daftar/detail proyek, dan paket. UI admin database tersedia untuk proyek, layanan, kategori/teknologi, media, kalkulator, booking/jadwal, inquiry, dan quote. Form publik booking, inquiry, dan quote memakai Server Actions. Rilis 2 tetap tertutup; tidak ada deployment atau verifikasi produksi.

Database dev berisi 6 proyek terbit (3 unggulan), 4 layanan aktif, 9 FAQ aktif, dan 6 media final dengan 24 varian WebP. Data paket/add-on/kalkulator/jadwal foundation tetap dipertahankan. Dua kandidat testimoni dan empat kandidat FAQ homepage tetap ditahan. Tidak ada record transaksi/pelanggan palsu. Status akun dan faktor MFA harus diverifikasi pemilik pada target yang disetujui; dokumen ini tidak menyimpan status atau kredensial akun.

## Status kode backend dan integrasi

- **Settings:** validasi Zod, izin per tab, editor tidak boleh mengubah konfigurasi booking, store Drizzle, audit dalam transaksi, dan invalidasi tag `settings` setelah commit melalui callback yang wajib diberikan. Kegagalan invalidasi dilaporkan berbeda dari kegagalan transaksi. Penggunaan adapter Next.js `invalidateSettingsCache` harus dari Server Action atau Route Handler.
- **Rich text:** `legal.privacyPolicy` dan `tracking.revisionPolicy` memakai format JSON terbatas dan berversi di `src/schemas/rich-text.ts`. FAQ publik mempunyai renderer berbasis node React; editor CMS dan renderer umum untuk legal/tracking belum tersedia. Halaman kebijakan privasi dan ketentuan layanan menyatakan status draf; persetujuan pemilik/legal tetap diperlukan.
- **Identitas:** skema Better Auth, profil `owner`/`editor`, foreign key aktor audit, signup tertutup, plugin TOTP, dan `requireAdminSession`. Pengecekan mensyaratkan bukti MFA untuk **sesi tersebut**, bukan hanya flag 2FA akun. Login, enrollment, TOTP, dan recovery memakai endpoint aplikasi; mutasi generik Better Auth tidak diekspos. Tes flow Better Auth in-memory mencakup enrollment, TOTP, recovery, dan bukti sesi. Tes integrasi Neon menguji pembuatan/pengelolaan profil admin, tetapi belum menguji seluruh login/TOTP melalui adapter dan HTTP nyata.
- **Bootstrap owner:** `pnpm owner:create` membaca `.env*` melalui `@next/env`, meminta target direct yang disetujui, input akun lewat terminal, konfirmasi nama database, dan `CREATE-OWNER`. Operasi selalu mengabaikan `TEST_DATABASE_URL`, tidak menampilkan connection string/password, dan tidak menjalankan migrasi. Status akun harus diperiksa secara read-only sebelum bootstrap; CLI end-to-end belum menjadi gerbang rilis. Panduan operator: `docs/backend/OWNER_BOOTSTRAP.md`.
- **Pembatas login:** endpoint login aplikasi memakai hash email, jendela bergulir 15 menit, dan penguncian 15 menit setelah lima kegagalan. Verifikasi password diserialkan di bawah row lock; pool database untuk lock dan Better Auth harus berasal dari dua koneksi `createDatabase` yang berbeda agar tidak deadlock. Pengujian login paralel sudah lulus pada PostgreSQL/Neon; TOTP belum diuji paralel melalui transport.
- **Rotasi sesi enrollment:** Better Auth 1.7.14 dapat mengaktifkan faktor dan mengganti cookie, tetapi masih mengembalikan token lama dalam JSON. `confirmTotpEnrollment` kini menggabungkan Set-Cookie hasil verifikasi ke Cookie request internal, membaca sesi aktif kembali, mencocokkan identitas, lalu mencatat assurance pada token baru. Tes regresi menolak token yang sudah dihapus; tidak ada bypass MFA atau assurance manual untuk akun pemilik.
- **Booking:** validasi input, pembacaan jadwal terbaru dalam transaksi, perhitungan ulang slot WIB, referensi CSPRNG, pencatatan audit, tautan Google Calendar, dan penanganan benturan. Konfirmasi owner memvalidasi URL pertemuan dan membentuk pesan WhatsApp. Migrasi SQL khusus `0005_booking_no_overlap.sql` menyiapkan exclusion constraint untuk booking aktif. Pengelolaan jadwal mingguan dan tanggal terblokir memakai lock yang sama. Public/admin Server Actions dan UI publik/admin booking/jadwal terhubung; uji alur HTTP dengan akun nyata masih menunggu login dan enrollment TOTP.
- **Perlindungan form:** fungsi verifikasi Turnstile dengan pemeriksaan hostname/action dan honeypot, HMAC IP, serta perintah SQL atomik untuk batas gabungan lima pengiriman form per IP per 15 menit. Rate limit dan alur form terkait diuji dalam suite integrasi Neon. Sumber IP harus berasal dari proxy tepercaya yang dikonfigurasi secara eksplisit; jangan memakai header kiriman klien tanpa validasi. Verifikasi Turnstile ke Cloudflare belum diuji.
- **Kalkulator dan quote:** skema grup/item/aturan/quote, validator graf konfigurasi, dan service quote yang membaca harga terbaru dari database, menghitung ulang di server, menyimpan snapshot dan audit, serta membentuk URL WhatsApp. Harga kiriman browser ditolak. CRUD admin mengganti grup/item/aturan secara atomik, memvalidasi grup wajib dan relasi, serta mengaudit perubahan. UI kalkulator membaca dan menyimpan konfigurasi lewat Server Actions; unit dan integrasi Neon lulus.
- **Kategori, layanan, paket, inquiry, teknologi, dan add-on:** service/store/action memvalidasi input dan izin serta mengaudit mutasi. UI database tersedia untuk kategori/teknologi, layanan, inquiry, dan quote. CRUD package/add-on memiliki action/domain, tetapi layar paket masih prototype dan belum tersambung. Inquiry publik memakai anti-spam, paket aktif, dan harga efektif server; UI publik mengirim melalui action. Add-on dan paket foundation tidak di-seed ulang.
- **FAQ:** service/action admin untuk membaca dan memutasi FAQ, audit transaksional, validasi isi aktif dan larangan FAQ tracking Rilis 2 tersedia. FAQ publik aktif masuk ke loader katalog beranda. Layar admin FAQ/testimoni masih prototype; tidak ada testimoni yang dibuat.
- **Projects dan media:** UI admin projects menggunakan action untuk CRUD, publish, trash/restore dan versi. UI media memakai signed upload ke staging privat lalu server memeriksa dan membuat varian WebP. Enam media impor telah difinalisasi ke R2; pemeriksaan ulang tidak menemukan objek `pending` di staging atau bucket publik. Upload baru tetap memerlukan konfigurasi R2 dev yang benar.
- **Pengguna admin dan audit:** hanya owner yang dapat membaca/membuat/mengubah profil admin. Password di-hash dan disimpan pada identitas Better Auth; perubahan melindungi owner aktif terakhir dan mencegah self-lockout. Audit log owner-only dan action tersedia, tetapi UI staf/audit belum terintegrasi ke action.
- **Seed dan import terpisah:** seed foundation mengisi Settings, jadwal, FAQ, kalkulator, dan paket tanpa menimpa data yang sudah ada. Importer `openbyte-frontend-r1` memiliki target dev/R2 yang dikunci; enam project, empat service, enam media, dan taksonomi telah diimpor, lalu dry-run berikutnya menunjukkan reuse tanpa duplikasi. Importer tidak mengaktifkan dua testimonial atau empat kandidat FAQ, tidak mengubah data transaksi, dan tidak memulihkan record trashed.
- Modul database, service, auth, seed berbasis database, dan keamanan ditandai `server-only`. Unit test memakai alias khusus karena berjalan di luar lingkungan React Server Components.

## Batas keamanan yang masih harus diselesaikan

1. Mutasi generik Better Auth sekarang ditutup di transport; hanya GET `/api/auth/get-session` yang diizinkan. Tetap pertahankan pemeriksaan sesi untuk setiap request, origin/CSRF pada POST aplikasi, dan bukti MFA yang terikat sesi. Sesi yang hanya melewati password tidak boleh menjadi sesi MFA setelah akun mengaktifkan TOTP.
2. Lockout login paralel sudah diuji terhadap PostgreSQL; plugin TOTP dan seluruh auth flow masih perlu verifikasi end-to-end. Pengambilan IP mentah Better Auth dinonaktifkan; enrollment memakai budget IP berbasis hash, sedangkan budget IP global untuk login/TOTP belum dipasang. Ambang budget global harus mengikuti kebijakan yang disetujui, bukan diasumsikan.
3. Penulisan jadwal dan blocked dates memakai lock singleton yang sama dengan booking. Pertahankan lock ini; exclusion constraint tetap menjadi penjaga terakhir terhadap booking tumpang tindih.
4. Referensi ID media di Settings belum didukung oleh kontrak/schema Settings. Jangan hubungkan field upload ke Settings sampai dukungan field-level dan validasi relasinya ditambahkan secara eksplisit.
5. Audit belum dibatasi append-only melalui role database. Kolom `diff` tidak boleh diisi dengan password, token, rahasia TOTP, recovery code, atau data sensitif lain.
6. Renderer rich text yang aman tersedia pada section FAQ; Page Builder dan preview draft berizin belum tersedia. Halaman privacy/terms berstatus draf dan perlu persetujuan. DTO Settings publik tersedia, tetapi semua copy/section belum dimigrasikan; halaman katalog memakai query dinamis, bukan cache `fetch` bertag.

`pnpm db:preflight` normal hanya menerima database bernama `*_test` atau `*_dev`. Suite integrasi harus memakai database test terisolasi yang sudah disetujui; jangan arahkan tes tulis ke database dev bersama atau produksi.

Verifikasi data sebelumnya memakai koneksi direct dan pooled pada target dev. Nilai environment, URL koneksi, host, nama database, status akun, dan kredensial tidak disimpan di dokumen ini. Jangan gunakan target dari environment lain tanpa persetujuan pemilik dan pemeriksaan target secara read-only.

Suite integrasi Neon mencakup CRUD konten, validasi relasi media/proyek/teknologi, kalkulator, profil admin, audit, bootstrap, serta constraint PostgreSQL yang terdaftar di `tests/integration/`. Enam aset katalog juga sudah melewati importer dan pipeline R2 dev. Ini bukan pengujian login/TOTP end-to-end lewat HTTP terhadap owner nyata, Turnstile Cloudflare, backup/restore, atau produksi. Branch dev bukan produksi dan tidak berarti backend siap produksi.

Migrasi `0005` berisi SQL kustom dan harus disertakan oleh migrator. `pnpm db:migrate` memakai `DATABASE_URI_DIRECT` (nama lama `DATABASE_DIRECT_URL` masih diterima) dan `DATABASE_MIGRATION_TARGET`; migrasi meminta konfirmasi target dan kata kunci. Seed/preflight memakai konfirmasi masing-masing. Skrip operator membaca `.env*` melalui `@next/env`; operasi owner tidak memilih `TEST_DATABASE_URL`, dan bootstrap memerlukan `OWNER_BOOTSTRAP_TARGET`, konfirmasi `CREATE-OWNER`, serta terminal interaktif. Tidak ada migrasi otomatis saat deploy atau CI.

### Catatan teknis yang ditemukan saat verifikasi

1. **Drizzle menimpa serializer postgres.js.** Saat `drizzle(client)` dibuat, tanggal dan JSON pada klien itu diteruskan tanpa serialisasi, sehingga `Date` mentah yang dikirim lewat tag `sql` biasa atau `db.execute` gagal di driver (`The "string" argument must be of type string`). Query builder bertipe Drizzle dan `db.execute` dengan parameter non-tanggal aman; **jangan** mengirim `Date` mentah lewat `db.execute`. Skema, booking, rate limit, dan settings sudah memakai jalur aman ini, dan tes integrasi memakai query builder bertipe untuk baris booking.
2. **Bentuk error constraint.** Driver melaporkan `code: "23P01"` dengan nama constraint di `constraint_name` (bukan `constraint`), dan Drizzle membungkusnya sebagai `cause`. `isBookingOverlap` karena itu mencocokkan SQLSTATE `23P01` saja — pada insert booking hanya ada satu exclusion constraint, jadi kode itu sudah cukup dan tidak rapuh terhadap perbedaan bentuk error.
3. **Deadlock gist.** Burst insert paralel pada exclusion index gist dapat menghasilkan `40P01` selain `23P01`. Tes menerima keduanya dan tetap menuntut tepat satu booking aktif.

Sebagian besar unit test memakai store/respons layanan tiruan. Ada pengujian signup dan TOTP Better Auth dengan adapter in-memory, tetapi itu **tidak membuktikan** kompatibilitas seluruh auth flow melalui HTTP/adapter di Neon. Store CRUD memiliki bukti tambahan dari integrasi PostgreSQL; pipeline R2 dev sudah dipakai untuk konten katalog, tetapi Turnstile dan backup/restore belum diverifikasi.

`pnpm test:integration` disiapkan terpisah dan tidak menjalankan migrasi. Tes ini membutuhkan database test yang boleh ditulisi dan dibersihkan, sudah dimigrasi dan di-seed secara manual, dengan nama berakhiran `_test` atau `-test`. Tetapkan `TEST_DATABASE_URL`, `TEST_DATABASE_TARGET` (`host:port/nama_database` atau `host/nama_database`), dan `TEST_DATABASE_WRITE_CONFIRM=I_CONFIRM_ISOLATED_TEST_DATABASE` pada proses lokal tanpa membagikan URL/kredensial di chat. Guard menolak target yang host+database-nya sama dengan `DATABASE_URL`, `DATABASE_URI`, `DATABASE_URI_DIRECT`, atau `DATABASE_DIRECT_URL` pada proses tersebut; setelah migrasi/seed, hapus variabel koneksi tersebut dari environment proses pengujian. Guard tidak dapat membuktikan bahwa endpoint pooled dan direct mengarah ke branch Neon yang berbeda, jadi operator tetap wajib memverifikasi isolasi branch secara eksplisit. Tes membuat dan membersihkan record uji dengan ID acak dan tidak aman dijalankan pada database yang berisi data produksi. Langkah penyiapan ada di `docs/backend/SETUP_DATABASE_TEST.md`.

Belum ada deploy atau verifikasi database produksi. `/health` mencoba `SELECT 1` dan mengembalikan 200 saat database tersambung atau 503 bila tidak siap. Pekerjaan tersisa mencakup login/TOTP pada lingkungan yang disetujui, integrasi sebagian layar CMS, verifikasi Turnstile, monitoring, backup/restore, dan pemeriksaan rilis. Setelah override `esbuild`, audit dependency tidak menemukan advisory produksi yang diketahui; typecheck, lint, 237 unit test, dan build lulus pada 31 Oktober 2026. Tes integrasi tidak dijalankan ulang.
