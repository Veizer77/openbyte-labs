## 2. Prosedur pasca-rilis

Semua perintah operator memakai koneksi **direct** (bukan `-pooler`) dan
konfirmasi target eksplisit. Tidak ada nilai kredensial yang boleh dicetak.

### 2.1 Migrasi

```powershell
# 1. Set koneksi langsung + target yang disetujui (dari secret manager, jangan dari dokumen)
$env:DATABASE_URI_DIRECT       = "<URI direct>"
$env:DATABASE_MIGRATION_TARGET = "<host>/openbyte_labs"

# 2. Migrasi (keyword MIGRATE)
pnpm db:migrate -- --confirm-target=openbyte_labs --confirm-keyword=MIGRATE
```

### 2.2 Preflight (read-only)

```powershell
$env:DATABASE_URI_DIRECT       = "<URI direct>"
$env:DATABASE_PREFLIGHT_TARGET = "<host>/openbyte_labs"
pnpm db:preflight -- --allow-production --confirm-target=openbyte_labs --confirm-keyword=PRODUCTION-READONLY
```

Harapan: 45 tabel, 20 migrasi, exclusion constraint booking, constraint booking
masa depan, 4 marker seed, settings singleton, dan baris seed.

### 2.3 Sinkronisasi konten dev → produksi

Idempotent (delete-then-insert dalam satu transaksi). Menyalin `media`,
`projects`, `project_categories`, `project_technologies`, `technologies`,
`categories`, `service_addons`, `testimonials`. **Tidak** menyalin identitas
admin, audit, rate limit, seed marker, atau `site_settings`.

```powershell
$env:SYNC_SOURCE_URI     = "<URI dev>"
$env:SYNC_DEST_URI       = "<URI produksi>"
$env:SYNC_SOURCE_TARGET  = "<host dev>/openbyte_labs_dev"
$env:SYNC_DEST_TARGET    = "<host produksi>/openbyte_labs"

pnpm db:sync:content -- --dry-run --confirm-target=openbyte_labs --confirm-keyword=SYNC-CONTENT
pnpm db:sync:content -- --confirm-target=openbyte_labs --confirm-keyword=SYNC-CONTENT
```

Baris dicocokkan lewat natural key (slug/key/nama), bukan UUID.

> **Peringatan JSONB:** driver `postgres` mengembalikan kolom `jsonb` sebagai
> objek JS. Menulis ulang dengan `JSON.stringify` akan menghasilkan *double
> encode* (`"[]"` sebagai string, bukan array). Selalu pakai helper `tx.json(v)`.
> Kesalahan ini pernah terjadi saat menyalin `site_settings` dev → prod dan
> seluruh transaksi di-rollback tanpa mengubah data produksi.

### 2.4 Backup

`pnpm db:backup` memerlukan kredensial backup khusus (bucket R2 terpisah +
`BACKUP_ENCRYPTION_KEY` ≥32) yang belum tersedia. Selama itu belum diisi,
gunakan salah satu:

- **Snapshot Neon** — `create_snapshot` pada branch `main`. Kuota snapshot
  project ini 1, jadi hapus snapshot lama sebelum membuat yang baru.
- **Dump lokal** — `pg_dump --format=custom --no-owner --no-privileges`, simpan
  **di luar repo** (folder `backups/` dan pola `*.dump` sudah git-ignored).

### 2.5 Akun admin

Produksi memakai satu akun owner (`samsungxse@gmail.com`) dengan peran `owner`,
status aktif, dan 1 baris `auth_two_factor` (TOTP terverifikasi + backup codes).
Bootstrap awal hanya boleh lewat `pnpm owner:create` di terminal interaktif
(lihat `docs/backend/OWNER_BOOTSTRAP.md`).

**Penting:** secret TOTP tersimpan terenkripsi dengan `BETTER_AUTH_SECRET`.
Menyalin akun antar-lingkungan hanya sah bila secret kedua lingkungan identik;
`scripts/copy-admin-identity.ts` menolak berjalan bila secret tujuan tidak dapat
mendekripsi secret TOTP sumber.

### 2.6 Mengubah environment variable

1. `npx vercel env rm <NAMA> production --yes`
2. `npx vercel env add <NAMA> production` (nilai dibaca dari stdin, tidak dicetak)
3. `npx vercel redeploy <url-deployment-production-terakhir>`

Env baru **tidak** berlaku pada deployment yang sudah ada; langkah 3 wajib.
Untuk perubahan kode, cukup push ke `main`.

### 3.1 Perilaku indexing (aktif)

Diverifikasi di produksi pada 4 November 2026:

| Permukaan | Perilaku terverifikasi |
|---|---|
| `robots.txt` | `Allow: /` dengan `Disallow: /admin`, `/tracking`, `/api`, `/pesan`, `/konsultasi` + baris `Sitemap:` |
| `/sitemap.xml` | HTTP 200, **17 URL**: 7 halaman statis + 6 proyek + 4 layanan |
| Meta robots | `index, follow` di `/`, `/paket`, `/proyek`, `/kalkulator` |
| Header `x-robots-tag` | Tidak lagi dikirim untuk rute publik; tetap `noindex, nofollow` untuk `/admin/*`, `/tracking/*`, `/api/*` |
| `/blog` | **Dikecualikan** dari sitemap dan selalu `noindex, nofollow` |

`/blog` dikecualikan karena modul editorial belum ada sehingga halaman itu selalu
menampilkan keadaan kosong ("Belum ada artikel yang diterbitkan"). Halaman tetap
bisa diakses (200) tetapi tidak layak diindeks. Penjaga ini dikunci oleh
`tests/unit/blog-indexing.test.ts`.

### 3.2 Sentry

- `src/instrumentation.ts` — `register()` menginisialisasi SDK server hanya bila
  `NEXT_RUNTIME === "nodejs"`, `SENTRY_DSN` terisi, dan `NODE_ENV === "production"`.
  `onRequestError` meneruskan error request ke Sentry.
- `src/instrumentation-client.ts` — inisialisasi klien dengan `NEXT_PUBLIC_SENTRY_DSN`,
  replay dan tracing dimatikan (`tracesSampleRate: 0`).
- `src/lib/monitoring.ts` — `beforeSend` membuang `user`, `request`, `breadcrumbs`,
  `extra`, `contexts`, `tags`, isi variabel frame, dan menormalkan pesan menjadi
  "Application error". Stack trace tetap dikirim agar error bisa dilacak tanpa
  membocorkan data pengguna.

Bukti aktif: DSN valid, endpoint ingest merespons `401` untuk request tanpa auth
(endpoint hidup), DSN ter-embed di chunk client produksi, dan **event uji
diterima Sentry dengan HTTP 200 + event id** (tag `verification=release-1`,
sudah dapat dihapus dari dashboard).

**Keterbatasan:** `SENTRY_AUTH_TOKEN` belum dipasang, sehingga source map tidak
di-upload dan stack trace di dashboard masih ter-minify. Tidak menghalangi rilis;
tambahkan token bila trace mentah dibutuhkan.

### 3.3 Turnstile

Kunci produksi terpasang dan berpasangan benar: `siteverify` dengan token dummy
mengembalikan `invalid-input-response` (artinya secret dikenali Cloudflare).
`src/env.ts` menolak boot produksi tanpa kedua kunci.

CSP di `src/proxy.ts` membatasi `script-src`/`frame-src`/`connect-src` ke
`challenges.cloudflare.com` beserta subdomain pelanggannya.

> **Konsekuensi:** custom domain menuntut **kunci Turnstile baru** karena kunci
> terikat hostname. Mengganti domain tidak cukup dengan mengubah DNS.

### 3.4 R2 (aset media)

Variabel R2 terpasang dan berlaku di runtime, 9 baris `media` merujuk objek di
bucket publik.

> **Masalah jaringan yang belum tuntas:** host `pub-56e1d9e9745541f7bbe1141aa7cc3be3.r2.dev`
> resolve ke `202.3.218.139` dengan sertifikat `CN=internetbaik.telkomsel.com`,
> sehingga browser menolak dengan `SEC_E_WRONG_PRINCIPAL` /
> `ERR_CERT_COMMON_NAME_INVALID`. Gejala sama di localhost **dan** produksi, dan
> tidak berubah setelah redeploy — indikasinya DNS/ISP hijack pada jaringan
> operator, bukan bug aplikasi. Gambar akan normal pada jaringan lain. Bila
> ternyata bukan hijack, tindakan berikutnya adalah memasang custom domain untuk
> bucket R2 (yang sekaligus menyelesaikan soal kunci Turnstile di atas).

### Catatan jujur atas dua hal

1. **Submission form asli belum dijalankan otomatis.** Uji anti-spam otomatis
   membuktikan jalur penolakan bekerja (4/4 `anti_spam`, 0 data uji tercipta, 0
   budget terpakai), tetapi token Turnstile sungguhan tidak dapat diperoleh dari
   browser otomatis: challenge Cloudflare tidak selesai bahkan pada halaman polos
   tanpa CSP dengan test-key yang memaksa challenge. Ini perilaku anti-bot yang
   benar, bukan bug. **Satu submission asli per form (`/kalkulator`, `/pesan`,
   `/konsultasi`) masih perlu dilakukan manusia dengan browser biasa** — budget
   anti-spam 5 per 15 menit per IP, jadi jangan diulang.
2. **Monitoring 24 jam belum dijalankan.** Sentry siap menerima event, tetapi
   jendela pemantauan pasca-launch (Sentry + Vercel runtime logs + Neon compute)
   baru bisa dinilai setelah 24 jam operasi nyata.

## 6. Catatan keamanan

- Kredensial produksi pernah tampil di transkrip sesi agen pada 3 Nov 2026.
  Rotasi **ditunda atas keputusan pemilik**; catat sebagai risiko diterima dan
  rotasi sebelum membagikan akses lebih luas.
- Dev-bypass admin (`/api/admin/dev-login`) hanya aktif bila
  `NODE_ENV !== "production"` **dan** `DEV_ADMIN_QUICK_LOGIN=true`. Variabel itu
  tidak ada di produksi; endpoint mengembalikan 403 di produksi.
- Smoke produksi menolak soft-404: rute negatif wajib berstatus tepat 404.
- `TRACKING_SESSION_SECRET` tidak dipakai di kode; boleh dikosongkan.
- Semua nilai secret hanya ditulis lewat stdin `vercel env add`, tidak pernah
  dicetak ke log atau disimpan di dokumen.
