## 2. Prosedur pasca-rilis

Semua perintah operator memakai koneksi **direct** (bukan `-pooler`) dan
konfirmasi target eksplisit. Tidak ada nilai kredensial yang boleh dicetak.

### 2.1 Migrasi

```powershell
# 1. Set koneksi langsung + target yang disetujui (dari secret manager, jangan dari dokumen)
$env:DATABASE_URI_DIRECT       = "<URI direct>"
$env:DATABASE_MIGRATION_TARGET = "<host>/openbyte_labs"

# 2. Migrasi (keyword MIGRATE)
pnpm db:migrate -- --confirm-target=openbyte_labs --confirm-keyword=MIGRATE
```

### 2.2 Preflight (read-only)

```powershell
$env:DATABASE_URI_DIRECT       = "<URI direct>"
$env:DATABASE_PREFLIGHT_TARGET = "<host>/openbyte_labs"
pnpm db:preflight -- --allow-production --confirm-target=openbyte_labs --confirm-keyword=PRODUCTION-READONLY
```

Harapan: 45 tabel, 20 migrasi, exclusion constraint booking, constraint booking
masa depan, 4 marker seed, settings singleton, dan baris seed.

### 2.3 Sinkronisasi konten dev → produksi

Idempotent (delete-then-insert dalam satu transaksi). Menyalin `media`,
`projects`, `project_categories`, `project_technologies`, `technologies`,
`categories`, `service_addons`, `testimonials`. **Tidak** menyalin identitas
admin, audit, rate limit, seed marker, atau `site_settings`.

```powershell
$env:SYNC_SOURCE_URI     = "<URI dev>"
$env:SYNC_DEST_URI       = "<URI produksi>"
$env:SYNC_SOURCE_TARGET  = "<host dev>/openbyte_labs_dev"
$env:SYNC_DEST_TARGET    = "<host produksi>/openbyte_labs"

pnpm db:sync:content -- --dry-run --confirm-target=openbyte_labs --confirm-keyword=SYNC-CONTENT
pnpm db:sync:content -- --confirm-target=openbyte_labs --confirm-keyword=SYNC-CONTENT
```

Baris dicocokkan lewat natural key (slug/key/nama), bukan UUID.

> **Peringatan JSONB:** driver `postgres` mengembalikan kolom `jsonb` sebagai
> objek JS. Menulis ulang dengan `JSON.stringify` akan menghasilkan *double
> encode* (`"[]"` sebagai string, bukan array). Selalu pakai helper `tx.json(v)`.
> Kesalahan ini pernah terjadi saat menyalin `site_settings` dev → prod dan
> seluruh transaksi di-rollback tanpa mengubah data produksi.

- bucket backup tidak boleh sama dengan `R2_BUCKET_PUBLIC`, `R2_BUCKET_STAGING`,

### 3.2 Sentry

- `src/instrumentation.ts` — `register()` menginisialisasi SDK server hanya bila
  `NEXT_RUNTIME === "nodejs"`, `SENTRY_DSN` terisi, dan `NODE_ENV === "production"`.
  `onRequestError` meneruskan error request ke Sentry.
- `src/instrumentation-client.ts` — inisialisasi klien dengan `NEXT_PUBLIC_SENTRY_DSN`,
  replay dan tracing dimatikan (`tracesSampleRate: 0`).
- `src/lib/monitoring.ts` — `beforeSend` membuang `user`, `request`, `breadcrumbs`,
  `extra`, `contexts`, `tags`, isi variabel frame, dan menormalkan pesan menjadi
  "Application error". Stack trace tetap dikirim agar error bisa dilacak tanpa
  membocorkan data pengguna.

Bukti aktif: DSN valid, endpoint ingest merespons `401` untuk request tanpa auth
(endpoint hidup), DSN ter-embed di chunk client produksi, dan **event uji
diterima Sentry dengan HTTP 200 + event id** (tag `verification=release-1`,
sudah dapat dihapus dari dashboard).

**Source map (build-time).** Upload artifact diaktifkan lewat `withSentryConfig`
di `next.config.ts`, bukan hanya dengan menambahkan token. Pembungkus itu
ber­gerbang: hanya dipakai bila `SENTRY_ORG`, `SENTRY_PROJECT`, dan
`SENTRY_AUTH_TOKEN` semuanya terisi. Job `quality` di CI hanya menjalankan
`pnpm build` tanpa ketiganya, sehingga build CI tetap `next build` biasa tanpa
menghubungi Sentry.

- `org`/`project` adalah slug (bukan secret). `SENTRY_AUTH_TOKEN` dibaca build
  plugin langsung dari environment; tidak pernah ditulis di `next.config.ts`.
- `widenClientFileUpload: true` ikut meng-upload chunk framework/Next internal.
- `deleteSourcemapsAfterUpload: true` menghapus `.map` dari output setelah
  percobaan upload, jadi source map tidak pernah ikut tersaji dari deployment.
- `telemetry: false`; `suppressOnRouterTransitionStartWarning: true` karena
  navigasi tracing memang dimatikan.

Bukti wiring: build lokal dengan token dummy memanggil Sentry dan gagal `401`
(artinya plugin benar-benar berjalan), dan
`tests/unit/sentry-build-wiring.test.ts` menjaga agar gerbang token tidak hilang
serta token tidak pernah masuk ke berkas konfigurasi.

**Bukti produksi (4 November 2026).** Deploy `dpl_3m4h5NvzQEFPX4hgz7yBEj97r4xp`
mencetak `[@sentry/nextjs - After Production Compile] Info: Successfully
uploaded source maps to Sentry` di build log. Pada deploy yang sama `/`, `/paket`,
`/proyek`, `/robots.txt`, `/sitemap.xml` = 200, `/health` =
`{"status":"ok","database":"connected"}`, dan setiap `/_next/static/**.js.map`
menjawab **403** sehingga source map tidak tersaji publik. Dua run CI terakhir
tetap `success`, membuktikan gerbang no-op bekerja tanpa token.

`SENTRY_ORG`/`SENTRY_PROJECT` diisi dengan ID numerik dari DSN
(`4512366287454208` / `4512370815401984`), bukan slug tekstual; Sentry menerima
keduanya. Keduanya bukan secret.

### Catatan jujur atas empat hal

1. **Submission form asli sudah dijalankan manusia (3/3 lulus).** Uji anti-spam
   otomatis sebelumnya membuktikan jalur penolakan bekerja (4/4 `anti_spam`, 0
   data uji tercipta, 0 budget terpakai), tetapi token Turnstile sungguhan tidak
   dapat diperoleh dari browser otomatis. Pemilik lalu menjalankan satu submission
   asli per form dengan browser biasa, semuanya diterima server:

   | Form | Referensi | Hasil |
   |---|---|---|
   | `/pesan?paket=starter-umkm` | `INQ-2611-V23Y` | diterima, tercatat di server |
   | `/kalkulator` | `QTE-2611-RSC6` | estimasi Rp 5.000.000–8.000.000, 28–42 hari, lanjut WhatsApp |
   | `/konsultasi` | `BKG-2611-Q76A` | 5 November 2026 10.00 WIB, Google Meet, menunggu konfirmasi admin |

   Jangan submit ulang: budget anti-spam 5 per 15 menit per IP.

2. **Monitoring 24 jam: dinilai, dengan satu mata yang belum tertutup.** Hasil
   lengkap ada di §4.1. Vercel (build, runtime error/fatal), Neon (operasi
   compute), dan DB (aktivitas + login gagal) semuanya bersih. Dashboard Sentry
   tidak dapat dibaca dari sesi agen karena tidak ada konektor Sentry dan token
   tersimpan sebagai secret ter-redact; pemilik perlu memeriksa sendiri.

3. **Backup otomatis: aktif dan terbukti. Restore drill: LULUS.** Lihat §2.4.
   Dua run backup `workflow_dispatch` sukses menghasilkan objek terenkripsi di
   bucket privat, dan header `OBLBKP01` membuktikan enkripsi AES-256-GCM benar
   benar diterapkan. Restore drill (`42153865695`) memulihkan dump ke container
   `postgres:17` terisolasi dan menghasilkan 55 tabel, 20 migration hash, serta
   exclusion constraint booking yang utuh — angka identik dengan produksi.

4. **Anomali booking 1 November 2026: selesai.** Pemilik mengonfirmasi baris
   tersebut adalah data uji miliknya sendiri, bukan kehilangan data. Tidak ada
   bug yang perlu diperbaiki; catatan ini ditutup.

## 6. Catatan keamanan

- Kredensial produksi pernah tampil di transkrip sesi agen pada 3 Nov 2026.
  Rotasi **ditunda atas keputusan pemilik**; catat sebagai risiko diterima dan
  rotasi sebelum membagikan akses lebih luas.
- Dev-bypass admin (`/api/admin/dev-login`) hanya aktif bila
  `NODE_ENV !== "production"` **dan** `DEV_ADMIN_QUICK_LOGIN=true`. Variabel itu
  tidak ada di produksi; endpoint mengembalikan 403 di produksi.
- Smoke produksi menolak soft-404: rute negatif wajib berstatus tepat 404.
- `TRACKING_SESSION_SECRET` tidak dipakai di kode; boleh dikosongkan.
- Semua nilai secret hanya ditulis lewat stdin `vercel env add`, tidak pernah
  dicetak ke log atau disimpan di dokumen.
